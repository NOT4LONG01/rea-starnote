## Setup failure (what was observed)
1. `bash qa/waydroid-up.sh` ran: weston started, `waydroid status` showed Session RUNNING / Container RUNNING, but `IP address: UNKNOWN`
   (never became an IPv4 address in 3+ minutes; /var/lib/misc/dnsmasq.waydroid0.leases is empty; veth is UP; `adb connect 192.168.240.112:5555` = "No route to host", neigh entry FAILED).
2. The weston window (screenshot `android-2026-10-14/00-weston-window.png`) is a blank grey screen: no Android UI.
3. /var/log/syslog (kernel messages from the container, readable via the adm group) shows Android's zygote being killed with signal 9
   and restarted every ~5 s since boot (`init: Service 'zygote' (pid N) received signal 9`, 43+ times between 21:05:58 and 21:09:26, never stabilising).
   So system_server dies repeatedly; Android never completes boot, so it never brings up eth0/DHCP/adbd.
4. Other lines seen around the first crash (symptoms, cause NOT established):
   - `libprocessgroup: Failed to make and chown /sys/fs/cgroup/uid_1000: Read-only file system` (also uid_0), `createProcessGroup(...) failed ... Read-only file system`,
     `Failed to open /dev/cpuset/foreground/tasks`, `/dev/stune/top-app/tasks: No such file or directory`, `init: failed to set task profiles`.
     /var/lib/waydroid/lxc/waydroid/config has `lxc.mount.auto = cgroup:ro sys:ro proc` on a cgroup2 host.
   - `binder_linux: <pid> cannot find target node` (46 times in the first 20 s) and `binder_linux ... ioctl c00c620f ... returned -22`.
   - Inference only: the read-only cgroup2 mount and/or binder behaviour on kernel 7.0 plausibly make system_server die. Not verified, because `waydroid logcat`/`waydroid shell` need root ("Action logcat needs root access").
5. I ruled out the ufw firewall as the cause of the missing IP: the zygote crash loop explains it, and /var/log/ufw.log has no BLOCK lines for waydroid0 or DHCP ports. (ufw is active with default INPUT/FORWARD DROP, so it may still need `sudo ufw allow in on waydroid0` + `sudo ufw route allow in on waydroid0` once Android boots; untested.)

## Change made to qa/waydroid-up.sh (only file edited)
Replaced the one-shot line
`IP="$(waydroid status | awk -F': *' '/IP address/{print $2}')"`
with a 90 s polling loop using `sed -n 's/^IP address:[[:space:]]*//p' | grep -E '^[0-9]+(\.[0-9]+){3}$'`.
Reasons observed: `waydroid status` separates fields with a TAB (the old awk returned "<TAB>UNKNOWN", producing `adb connect <TAB>UNKNOWN:5555`),
and the IP is `UNKNOWN` until Android's network is up. The edit is NOT verified end to end (no real IP ever appeared); it was only confirmed to exit with "no container IP yet" instead of using a bogus address.
Not changed (observation): the script prints Session RUNNING as soon as the container starts, even when Android is crash looping; it has no boot-health check.
